## 1. 一句话结论

> **环境/依赖/构建这三类坑的共同形状是:它们**不会报错** ——
> 程序照常启动、照常响应,只是**跑的根本不是你以为是的那份东西**。**
>
> 所以判据不能是"它起来了",必须是**"它跑的是哪一份"**。

---

## 2. 为什么:这些坑长什么样(形状 → 实例)

| 形状 | 实例(表面 → 实际) |
|---|---|
| **预构建的运行环境和源码不一致** | 容器**能启动、能响应** → 镜像是两个多月前构建的,跑的是**迁移前的旧代码**,连外部的服务商都回落了 |
| **依赖声明"下界无上界"** | `pkg>=1.2` 装得上、跑得通 → 半年后解析到大版本,API 已移除 ⇒ **必炸** |
| **"能调通"被当成"参数有效"** | 请求返回 `200`、有正常响应体 → 网关**根本不校验参数**(任意模型名都 200) |
| **本地/远程环境差异未记录** | 同一份代码在 A 处行、B 处不行,而差异(证书/代理/架构/镜像源)没人写下来 → 每次重查一遍 |
| **"某操作之后要做 X"的调用写错位置** | 代码"看起来做了这件事" → 它写在**模块级**,只在 `import` 时执行过一次 |

## 3. 规则

> 每条:规则(通用)→ 反例(实例)→ 正例(怎么做到)。

### `D1-R1` · 无界版本声明 = 定时炸弹

**规则**:依赖只写"下界无上界"(`pkg>=1.2`),等于把"未来某个大版本"的行为签进了今天的代码。
→ 要么**固定版本 / 锁定文件**,要么**声明上界**;升级要走一次**显式**动作。

- **反例(实例)**:依赖写 `pkg>=1.2`,半年后解析到大版本、其 API 已移除 ⇒ **必炸**。
- **正例**:锁定文件入库 + 定期显式升级(升级时跑回归)。

### `D1-R2` · 「能调通」≠「参数有效」

**规则**:很多网关/服务**不校验参数**(任意模型名、任意枚举值都可能返回 200)。
要验证有效性,必须以**官方文档**为准,或用**可区分的失败样例**(故意传一个必然无效的值,看它是否报错)。

- **反例(实例)**:换了模型名后"能调通",于是认为迁移完成 —— 而网关对任意名字都返回 200。
- **正例**:① 查官方文档确认名字/参数;② 用**已知无效**的输入做对照(它若不报错 ⇒ 该端点不校验,不能拿"通了"当证据)。

### `D1-R3` · 本地/远程环境差异**显式记录**

**规则**:同一份代码在两处行为不同时,**先怀疑环境**,并**当场把差异记下来**(记进项目的环境备查,而不是只留在聊天里)。
典型差异维度:**证书/代理 · 网络解析 · CPU 架构/轮子 · 镜像源 · 端口占用**。

- **反例(实例,5 例)**:TLS 拦截需指定系统 CA;`localhost` 解析到 IPv6 打到别的进程;
  Intel Mac 无对应 wheel 且本机无 Rust;国内镜像网速骤降;容器崩溃重启抢占端口。
- **正例**:在项目锚点维护一节「环境备查」,每条写**判别依据**(怎么区分)与**处置**;
  证据不足的写成"待观察",不要写成结论(见 `A1-R16`)。

### `D1-R4 ⚠️` · 三个"沉默的执行位置"陷阱(都很隐蔽,都真实发生)

**规则**:凡"某操作之后要做 X"的调用,**先检查它在不在会被执行的位置**。

1. **副作用函数写在模块级 = 只在 `import` 时执行一次。**
   *反例(实例)*:缓存失效调用被写在函数**外**(模块级)→ **增删数据后缓存永不失效**,
   表现为"刚上传的资料搜不到、**重启才好**"。
2. **`docker run --env-file` 不剥离行内 `#` 注释**(而常见 `.env` 解析库会剥离)。
   *反例(实例)*:`KEY=value   # 说明` 被**整行**当成 value(如模型名被注释污染)→ 请求被对端拒绝。
   需要时用 `-e` 显式覆盖关键变量。
3. **`.env` 加载器会把配置"灌回来"**(常用 `os.environ.setdefault`)。
   *反例(实例)*:测试里删掉环境变量想构造"未配置"场景,而配置加载器**又把它读回来了**
   → 测试**真的打到了线上服务**(花钱 + 发外网请求)。
   → 规则:测试要能**显式关闭配置加载**(给一个开关),而不是只删环境变量。

*来源:某评测门项目 · 2026-09-11。*

### `D1-R5` · 预构建的运行环境会撒谎

**规则**:用**预构建的运行环境**(容器镜像 / 虚拟机镜像 / 打包产物 / 虚拟环境 / 快照)跑**别人的代码**之前,
做两件事:① 对比**环境内文件**与**源码仓库文件**(如 `md5sum`);② 看**构建时间**。
不一致 ⇒ **不要直接用**:走"重建"或"挂载当前源码"两条路之一。

- **反例(实例)**:容器能启动、能响应,但镜像构建于**两个多月前**(早于一次依赖/服务商迁移)
  ⇒ 容器里跑的是**旧代码**,配置回落到了另一家服务商,而那家的额度早已耗尽。
  **"容器存在且能启动"完全不代表它跑的是当前代码。**
- **正例**:以**只读方式挂载源码目录**到运行环境内(镜像只负责依赖,代码永远是当前版本),
  或**重建镜像**;并在该运行方式的 README 里写明**退役条件**(官方构建路径可用即退役这一层)。

## 4. 适用场景与不适用场景

**适用**:

- **接入或评测外部系统**(服务、模型、容器、第三方 API);
- **换依赖 / 升版本 / 配环境 / 改启动方式**之后;
- 现象是"**能启动、能响应,但结果不对**",或"**两处行为不一致**"时。

**不适用 / 注意**:

- **己方可控、版本锁死的运行环境**(如固定 commit + 锁文件)不必每次重验 —— 但**首次接入必须验**;
- `D1-R2` 的对照探针**有成本**(会真调对方):至少做一次**最小真实调用**,不要退回"健康检查绿了就算";
- 环境差异**不是都要修**:有些只需**记录 + 绕开**(见 `D1-R3` 的处置栏)。

## 6. 怎么验证它被落地

| 规则 | 怎么验证(通用判据) |
|---|---|
| `D1-R1` | 仓库里存在**锁定文件**,且 CI 用锁定安装;依赖声明里没有"只有下界"的项 |
| `D1-R2` | 接入文档里记录了**官方来源**;并有一次**必然无效输入**的对照记录 |
| `D1-R3` | 项目锚点有「环境备查」节,每条带**判别依据 + 证据强度**;新增差异时**当轮**补写 |
| `D1-R4` | "某操作之后要做 X"的调用**都在函数体内**;测试能**显式关闭配置加载**(而不是删环境变量);`--env-file` 的行内注释已剥离或改用 `-e` |
| `D1-R5` | 接入前有**文件指纹/构建时间**的核对记录;该运行方式的文档里有**退役条件** |

**反检验**:任取一条,问 —— **"如果它被违反了,有没有东西会变红或出声?"** 答"没有" ⇒ 还没落地。
