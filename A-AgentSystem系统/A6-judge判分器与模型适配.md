## 1. 一句话结论(本文最值得留下的)

> **你写的规则,对你自明,对执行者不自明。**
>
> 你脑子里补上的那些"当然是这样"的边界情形,**不会**随规则一起传过去 ——
> 执行者会用**常识**补那个空,而常识在边界情形上恰好与规则相反。
> 然后**分歧会被记在"执行者不听话"或"模型不行"的账上**,而真正的责任人是你那份规则。

**这条与 `A5` 篇是一对**:`A5` 篇讲"你**自己**确认完成时判据会骗你";
本篇讲"你**让别人**判断时,你的规则会骗他"。

## 2. 为什么:一个现场

**背景**:要给"某个模型判分准不准"装一根外部锚 —— 做法是拉业务方人工标注 16 条真实答案
(每题给出:问 / 期望 / 语料依据 / 被测答案),再算"模型判定 ↔ 人工判定"的一致率。

**现象**:其中三条**结构完全相同**的条目(答案都是「无法回答…**但句中出现了期望里的关键词**」),
被标出了**互相矛盾**的标签 —— 一条判"不满足",另两条判"满足"。

**当时的规则不是没写**。标注表开头写着判据:"`answer_contains` = **含其一即符**(命中任意一个即满足,
**不要求全部命中**);判**语义**是否契合,不要求措辞完全一致"。这条规则**写对了**。

**真实原因**:规则没写到**它真正会被用到的那个边界**上 ——

> 「整句是拒答的时候,句中出现了关键词,**算不算**命中?」

这一格是**反直觉**的:规则说"字面命中即满足",而**常识**说"它根本没回答问题 ⇒ 不算"。
规则的作者(技术侧)觉得答案不言自明(规则原文就写着"含其一即符"嘛);
执行者(业务方)读到的是一句抽象规则,遇到具体句子时,**用常识补位** —— 于是同一形状给出了相反标签。

**代价**:若那批标签直接进入计算,**这根"外部锚"从一开始就是歪的** ——
而它错了**没有任何下游环节能发现**:它本身就是唯一的参照物。**这是一类"错了也测不出来"的缺陷。**

**旁证**:同一次校准还暴露了**模型**犯同一个错 —— 判分器的指令里同样只写了"含其一即符",
没写"拒答时也算",于是三条半拒答全部被判成 `flag`(存疑)。
把那一句边界补进指令后,一致率从 **0.80 直接升到 1.00**、存疑条目从 3 条降到 0 条。
⇒ **同一处缺失,同时坑了人和模型** —— 这正说明问题在**规则**这一层,不在"谁不听话"。

## 3. 规则

### A6-R1 · 给执行者写判据,要写到**反直觉的边界情形**上;写完自问"它最容易被常识推翻的地方在哪"

**规则(通用)**:

判据写完,**不要以"规则原文已经说清了"收工**。做一步额外动作:

1. 问自己:**"这条规则,在哪些具体情形下会被常识推翻?"** —— 通常只有 2–3 处;
2. 把那几处**写成具体例子**(不是再写一遍抽象规则),放进判据里;
3. 边界例子要**把"不要这么判"也写出来** —— 只写"应当如何"常常不够,
   因为执行者的常识会给出一个**看起来更合理**的相反答案,你得**指名它**。

**反例(真实实例)**:

- 标注表里写了「含其一即符」,**没写**「整句是拒答时也算命中」⇒ 三条同形状条目被标出相反标签
  (来源:`某评测门项目` M1 标注轮,2026-09-12)。
- 判分器的指令里同样只有「含其一即符」⇒ 模型对同一形状一律给"存疑"(`flag`)。
  补上那一句边界后:一致率 **0.80 → 1.00**,存疑 **3 → 0**。

**正例(怎么做到)**:

```
❌ 只写规则:
   answer_contains = 含其一即符(命中任意一个即满足)。

✅ 规则 + 边界例子:
   answer_contains = 含其一即符(命中任意一个即满足)。
   ⚠️ 边界(必须照此判,不要用常识替代):被测整句是**拒答**(如"无法回答""资料未提及")时,
      只要句中出现了任一候选词 ⇒ **即算满足**;不得因为"它没有真正回答所问"而改判。
```

> **本体化的做法**:给执行者的判据里,凡是"反直觉但必须遵守"的那一格,
> 都应当以**"⚠️ 边界"**的形式单独成条 —— 它比规则本体更值钱,因为它才是分歧的来源。

---

### A6-R2 · 参照集要**盲**:先让执行者判完,再给他看参考答案

**规则(通用)**:建人工参照集时,**先让标注人独立判完,再展示"系统判了什么"**。
否则他会锚定在系统的结论上 —— 那样得到的一致率**只是在测量你的引导**,不是测量系统的准确度。

配套三件事:

1. **参照集要自包含**:每条自带问题 / 期望 / 原始材料(语料、上下文),
   不要让标注人去翻别处 —— 翻不到就会猜,猜了你的数据就废了;
2. **允许"说不清"**,并**明确告诉他会被剔除**(否则他会硬猜 —— 硬猜出来的标签比"说不清"更毒);
3. **分歧条目要点名复核**(见 `A6-R3`)。

**反例**:标注材料若把"模型的判定"排在每条旁边,标注人会不自觉地"确认"它 ——
一致率会**虚高**,而虚高的一致率比没有更糟:它给了你一个错误的安心。

**正例**:把系统判定放进**附录**,并在表头写明"先标完再看附录";
标完后**当面过一遍分歧条目**(本实例正是这样才发现那三条矛盾的)。

### A6-R3 · 分歧要**分类**计数,不要只报一个总分;样本里必须能"判错"

**规则(通用)**,两条配套:

**(a) 总分不许单独出现。** 一个"0.80"说不清任何事。至少要拆成:

| 分类 | 含义 | 为什么单列 |
|---|---|---|
| 误杀 | 执行者判"满足"、系统判"不通过" | 代价最直接(好答案被拦) |
| 漏放 | 执行者判"不满足"、系统却通过 | 安全风险 |
| 拿不准(flag/存疑) | 系统**没给结论**,推给人 | **与"判错"不是一回事**;数量决定人工负担 |
| 剔除 | 说不清 / 用例本身有问题 | 决定样本覆盖够不够 |

> 本实例中 **0.80** 看着"差一点";拆开才发现 **3 条分歧全是"拿不准"**,
> 剔掉它们后 **1.00** —— 结论从"判得不够准"变成"**该定的不定**",处置方案完全不同
> (前者要重训/换模型,后者**只改一句边界说明**就解决了)。

**(b) 样本里必须有"系统可能错"的条目,否则这个数没有信息量。**
从"全对"的池子里抽样,得到的一定是满分 —— **一个"一律放行"的系统也能拿满分**。

**反例(真实实例)**:为省事,从最近一轮**全部通过**的结果里抽样做参照集 ——
那一批 45 条**全通过**,从里面抽 15 条,一致率必然是 1.00。**这个数什么也没测**。
正确做法:从**历史产物里的真实失败**中取(含"当时判错"的条目),再加少量"清晰对照"。

**正例(选样本的配方)**:

```
A 组:真实失败/被判不通过的真实答案(含**疑似误杀**的)—— 最值钱
B 组:历史上出现过分歧/存疑的条目(争议项)
C 组:清晰对照(直答、明确拒答)—— 用来检验"系统会不会把好的判坏"
```

> 本实例里最值钱的是"疑似误杀"那条:答案明显正确,只因期望里的候选词写法不全
> (大写/空格差异)而被判不通过 —— **只有人看得出来**,而这种条目在"全绿"的池子里**永远不会出现**。

### A6-R4 ⚠️ · 迁移到「推理型模型」必须复核三件事

**规则(通用)**:① 输出上限(`max_tokens`)要**留出推理额度**
(推理型模型先花 token 思考,额度太小则**正文一个字都出不来**,响应 `finish_reason=length` 且 `content` 为空);
② **模型返回必须校验非空**;③ 失败要**回退**(如回退到原始输入)而**不是静默降级**。
→ 规则:模型迁移是一次**系统性复核**(额度 / 空返回 / 回退),不是换个模型名就完事。

**反例(真实实例)**:某 RAG 系统把生成/改写模型迁到推理型,而查询改写仍传 `max_tokens=200`
→ 推理吃满额度 → 改写成**空串** → 检索用**空查询** → 召回到无关文档 → 系统一律回「无法回答」。
实测空返回率 **24%~93%**(随每次推理长度波动)。更隐蔽的是:**它没有任何语义特征** ——
回答格式正常、只是"答不出",看起来像"检索能力差"或"知识库没有"。
*来源:`某评测门项目` 阶段4-步骤8(该缺陷由评测门在真实链路抓出),2026-09-11。*

### A6-R5 ⚠️ · 零容忍判据的脆弱性,会伪装成"对方违规"

**规则(通用)**:凡**零容忍**判定被触发,
先做**三问归因**(① 对方真的做了禁止的事吗?② 这条判据是**怎么判**的?③ 判据**漏判/误判**的代价是什么?),
三问都指向"确实违规"才可**上报为质量问题**。
→ 规则:① 越是零容忍,越要把**判据的表达力**做够(如"词表命中" → "模式匹配",仍是确定性规则,不引入模型);
② 注意**结构性约束**:若体系要求这类判定"只能走确定性引擎",那就**不能用模型兜底**,只能把规则本身做稳;
③ 零容忍的**假阳性代价最高**,所以它的触发**最需要复核**。

**反例(真实实例)**:某硬判据是**关键词词表**,对方**实质已合规**但用了表外的说法
(表内只收「无法确定」,对方说的是「无法确认」)→ 判为"违规" → 触发**零容忍发布阻断**。
**一个措辞漏词 = 整批被拦。** *来源:`某评测门项目` 阶段4-步骤8(签核 D-13 修复),2026-09-11。*

## 4. 适用场景与不适用场景

**适用**:

- 建人工参照集 / 黄金标准 / 校准样本(标注、评审、验收、外包质检);
- 给**另一个 Agent** 派"按判据做判断"的活(此时 A6-R1 尤其关键:Agent 的"常识"来自训练分布,
  它不会来问你,会直接补位);
- 任何"一致率 / 准确率 / 通过率"要报给人看的场合(A6-R3);
- **换模型**(尤其换成推理型模型)或判据里含**零容忍**项时(→ `A6-R4` / `A6-R5`)。

**不适用**:

- 判据本身**没有边界歧义**(例如纯格式校验:JSON 能否解析)—— 无需 A6-R1 的边界例子;
- 你**只想要快速信号**、不打算据此做决定 —— 那不要建参照集,别假装有外部锚。

## 6. 怎么验证它被落地

1. **可证伪的自查句**:交出判据前问 —— **"这条规则最容易被常识推翻的那一格,我写出来了吗?"**
   答不上来 ⇒ 补上,再交出去。
2. **参照集自查**:随机挑 3 条,**答案能不能一眼判出来**?不能 ⇒ 材料不全(缺语料/缺上下文)。
3. **报告自查**:如果我只报一个总分,**对方能据此决定下一步做什么吗**?
   不能 ⇒ 按 `A6-R3` 的表拆开。
4. **样本自查**:**"如果我系统一律输出 pass/一律输出 fail,这个数会怎样?"**
   答案接近满分 ⇒ 样本废了,重取。
