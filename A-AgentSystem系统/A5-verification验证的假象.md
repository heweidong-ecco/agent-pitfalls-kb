## 1. 一句话结论(本文最值得留下的)

> **验证不是"我做了验证动作",而是"这个验证动作真的能失败"。**
>
> **一个从来没红过的检查,和一个没有检查,区别只在于:前者更有欺骗性** ——
> 它会让人以为"已经验过了"。

**推论(可直接照做)**:每写一个检查,先问一句 —— **"要让它变红,得发生什么?"**
如果答不出来,这个检查就不算成立。

## 2. 为什么:六个现场(形状不同,根因同一个)

> 六个案例来自**同一次连续工作**(`某评测门项目` · 阶段4-步骤8,2026-09-11 ~ 09-12)。
> 下表左列是**通用形状**,右列是**当时的实例** —— 便于你认出自己的场景。

| 通用形状 | 实例(来龙去脉) | 表面 | 实际 |
|---|---|---|---|
| **重复执行的实验,每轮其实没变** | 统计 A/B 跑 20 轮 | 有 N、有检出率、有 p 值,**格式全对** | 每轮用同一颗随机种子 ⇒ 20 轮 = 1 次运行的 20 份拷贝;轮间方差恒 0 |
| **测试绕开了会犯错的那条路** | 安全用例验证"外部返回畸形文本会不会把被测系统打崩" | 用例**通过** | 用例没开生产默认开启的**观测**开关,而崩的正是观测路径上的函数 |
| **"能启动"被当成了"能干活"** | 接入一个外部服务 | 健康检查 **200**(依赖全 ok) | 一次真实业务请求立刻 500 |
| **预构建的运行环境和源码不一致** | 用容器跑一个外部项目 | 容器**能启动、能响应** | 镜像构建于两个多月前 ⇒ 跑的是**旧代码**,连它对外的服务商都回落了(**该条规则已迁至 `D1-R5`**) |
| **自己的启发式脚本被当成了结论** | 为"补齐知识库"写脚本扫缺口 | 脚本**输出一份缺口清单** | 两个脚本**一个漏报、一个误报**;照它动手会改错一批数据 |
| **边界值"中性"与"无法计算"混为一谈** | 计算两组样本的效应量 | 得到一个 **`0.0`** | 两组都零方差时该指标**无法计算**,却被当成"**效应为零**" |

**共同点**:每一步**都没有报错、没有变红**,甚至**没有可疑之处**。
它们的产物是"**像结论的东西**"—— 这才是它们贵的原因。

## 3. 规则

> 每条:规则(通用)→ 反例(实例)→ 正例(怎么做到)。

### A5-R1 · 重复 N 次的实验,必须断言"重复之间确实不同"

**规则**:凡"跑 N 轮 / 调 N 次 / 采样 N 次",必须有**可执行的断言**证明重复之间真的不同 ——
取值多样性 > 1 **或** 逐轮种子/输入不同 **或** 方差 > 0。断言**写进测试**,不写进注释。

- **反例(实例)**:统计 A/B 驱动"跑 20 轮",每轮新建评估器却传**同一颗种子**
  ⇒ N 轮是同一次运行的 N 份拷贝:轮间方差恒 0 → 效应量判定为"无法计算" → p 恒为 1
  ⇒ **整条 N 曲线失去意义**。而输出**完全正常**(有 N、有检出率、有 p 值)。
  *来源:`某评测门项目` · 2026-09-11 · 阶段4-步骤8。*
- **正例**:让重复单元**逐轮取不同种子**(如 `make(x, base_seed + i)`);
  并加一条**回归守卫**,断言"N 次取值不止一种"。
  ⇒ **"N 次"里的 N,必须有东西守着它不是装饰。**

### A5-R2 · 测试必须走"生产默认路径"

**规则**:写测试前先问 —— **"生产默认配置是什么?我这个调用与它差在哪?"**
差在**关键开关**上(观测/日志采样、阈值来源、并发模式、鉴权、缓存)时,**按生产默认写**;
若有意不同,必须在测试里写明理由。

- **反例(实例)**:一个安全用例验证"外部返回畸形文本会不会把系统打崩",但用例**没开观测**;
  而生产默认是**开着观测**的,且**崩的正是观测路径上的一个函数**。
  ⇒ 用例**通过**,生产中这条路会崩。**测试给了一个假的安全感。**
  *来源:同上,2026-09-11。*
- **正例**:该用例显式按生产默认打开观测,并在注释写明"生产默认开启,故必须开";
  再补一条**直接调用入口函数**的用例,把两条路都覆盖。

### A5-R3 · "能启动"≠"能干活":先打一次真实业务请求

**规则**:接入任何外部系统(服务 / 模型 / 数据库 / 第三方 API),**第一件事是发一次真实业务请求**,
并校验**业务层面的成功** —— 不是端口通、不是 HTTP 200、不是健康检查绿。
探针失败时:**先归因环境与依赖,归因不清就不要跑正式轮次。**

- **反例(实例)**:健康检查返回 `{"status":"healthy","checks":{"database":"ok","redis":"ok"}}`,
  看起来万事俱备;发一条真实业务提问立刻 **500**。
  若不做这一步就跑完整评测,结果形态是"一批失败"—— **会被读成"对方质量崩了"**。
  *来源:同上,2026-09-11。*
- **正例**:把探针**固化进启动脚本**,并给它一个**独立退出码**(如 `2 = 起来了但答不了`),
  与"起不来"(`1`)分开。⇒ 让**环境问题**与**质量问题**在退出码上就分开。

### A5-R4 · 启发式判据只是代理指标 —— 两端都会错

**规则**:任何**启发式 / 关键词 / 正则 / 近似**判据都只是**代理指标**。
使用前**先拿已知答案的样本验它**:至少一个**已知为正**、一个**已知为负**。
启发式只允许用于**初筛 / 排序**;**结论必须回落到真实数据**。

- **反例(实例)**:为"一次性补齐知识库"写了两个缺口扫描脚本 ——
  ① 关键词扫描**漏报**(判"0 缺口",而实证有 3 条真实失败);
  ② 同篇共现扫描**误报**(把**实际通过**的 5 条列为缺口)。
  ⇒ 若照它动手,会**改错一批数据**(误报的被无谓补写,漏报的仍然失败)。
  根因:两个判据都只是**代理指标**,而使用者**没验证就直接采信了输出**。
  *来源:同上,2026-09-12。*
- **正例**:改用**真跑结果**作为唯一可信来源(缺口 = 真跑失败且召回切题的那些);
  启发式脚本降级为**辅助排序**,且输出里必须标注"**这是代理指标,不是结论**"。

### A5-R5 · 边界返回值:先问"下游会把它读成什么"

**规则**:为**退化 / 边界输入**设计返回值时,先问"**下游拿到它会得出什么结论**"。
严格区分「**值 = 中性**」与「**值 = 无法计算**」:后者用空值/显式未定义表达,**绝不要用 0**。

- **反例(实例)**:一个效应量函数在"两组都零方差"时返回 **`0.0`**(理由是"不想返回 NaN/inf")。
  可 `0.0` 在语义上等于"**没有差异**" ⇒ 一个**稳定的 10 个百分点退化**被判成"无差异"。
  这是**结构性假阴性**:不是算错,是**语义错**。
  *来源:同上,2026-09-11。*
- **正例**:返回**未定义**(空值),判定层显式给出**回落规则**(如"显著 **且** 均值不同 → 按方向判"),
  并把这条回落**写进文档字符串与测试** ⇒ 让"**算不出来**"和"**算出来是零**"在下游可区分。

### A5-R6 · 判据必须匹配**被判定对象的机制**

**规则**:用某个判据下结论前,先确认**这个判据在你的场景里是否成立**。
尤其这些"看起来通用"的判据**依赖机制假设**:

| 你想判定 | 常见判据 | **在什么机制下才成立** |
|---|---|---|
| 分支是否已合入主干 | `git merge-base --is-ancestor <branch> <main>` | **仅 merge commit 模式**。squash / rebase 会在主干上**新建提交** ⇒ 原分支 commit 从来不是祖先 ⇒ **结构性失效**(不是精度问题) |
| 文件是否已在某分支 | 同上 | 同上;应改用**内容判据** |
| 提交是否已推送 | 本地 log 有这条 | 与远端无关;须比对远端 ref |

- **反例(实例)**:收尾时用祖先关系逐个核 7 个分支,全部报"未合并" —— 而它们的合并请求**全部显示已合并**。
  若信了它:要么**误判工作没完成**(可能重复推送/重复建 PR),要么**以为删除不安全**而留下一堆陈旧分支。
  两种都不会报错。*来源:见 §5。*
- **正例**:先确认仓库的**合并模式**(看历史里有没有 merge commit / 查仓库设置),再选判据:
  squash/rebase 模式下用**内容判据**(查合并请求状态 + 逐文件确认目标分支含该内容),
  并在报告里写明"**我用的是内容判据,因为本仓是 squash**"。

## 4. 适用场景与不适用场景

**适用**:
- 编写任何**测试 / 实验 / 度量 / 校验脚本 / 归因脚本**;
- **接入或评测外部系统**(服务、模型、容器、第三方 API);
- 拿到一个"全绿 / 有数字 / 有结论"的结果,**准备据此下判断**时。

**不适用 / 注意**:
- **一次性探索**(直接打印看一眼)不需要 N 轮断言 —— 但**探索结论不得直接当证据**;
- A5-R3 的探针**有成本**(会真调对方);若探针很贵,至少做**最小真实调用**,不要退回"健康检查";
- A5-R4 不是"禁止用启发式",而是"**禁止不验证就采信启发式**";
- A5-R1 不适用于**确定性单次检查**(如"这个文件存在吗")。
